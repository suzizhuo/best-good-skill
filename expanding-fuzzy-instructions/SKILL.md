# Expanding Fuzzy Instructions 模糊指令扩展

## Overview

主代理收到模糊指令，第一动作是派子代理：不猜、不仓促交付。模糊指令的价值恰恰在没写死的那部分——扩展没完成就交付，等于替用户做决定。主代理上下文只装调度记录和清单，执行细节全部压子代理：主代理不被上下文污染，清单扩到毫无遗漏。

## Iron Law

```
原话表 + 扩展清单未建成前，不交付。
省掉清单直接交付 = 违规。
免扩展判据只有一项：对象、程度、基准三项参数均能从用户消息逐字引出。
```

条目不执行就没有扩展；纸上走了流程手里没表，同样没扩展。

## When to Use

- 用户指令模糊、短、边界不明（「搞一下那个」「弄一下」「全套流程」）
- 指令看似完整但关键参数缺失：哪个对象、做到什么程度、按哪份基准
- 主代理意识到自己想「先干为快」

不用于：对象、程度、基准三项均能从用户消息逐字引出（确切对象、可引用标准、参照基准都在原文里）——直接执行。

措辞口径：「内容你定」「你看着办」等授权性措辞按参数待定信号处理；「快点」「别走流程」等催促性措辞是成本表述，不改判据。

## Flow

```dot
digraph fuzzy_loop {
    rankdir=LR;
    recv [label="收到模糊指令", shape=box];
    fuzzy [label="派模糊子代理\n原话表+初始清单+裁定列", shape=box];
    split [label="并行：断言子代理\n+ 分析子代理", shape=box];
    rewrite [label="主代理改写清单\n五列记账", shape=box];
    merge [label="合并子代理再派\n模糊子代理", shape=box];
    new [label="有新条目？", shape=diamond];
    exec [label="按清单执行\n逐条销项", shape=box];
    recv -> fuzzy -> split -> rewrite -> merge -> new;
    new -> rewrite [label="是"];
    new -> exec [label="否（扩不出）"];
}
```

## Steps

1. **FUZZY（建表）** — 按 `fuzzy-dispatch.md` §2 模板派模糊子代理。派发 prompt = 用户原话逐字 + 任务边界 + 运行时口径继承（组装方式见模板）。返回三件：原话表（原话逐字分段 + 每段字面义 + 每段延伸方向）、初始扩展清单（编号，含意图/边界/依赖）、裁定列（每条的可执行性结论由该子代理给出）。
2. **SPLIT（并行）** — 一轮内并行派两个子代理：
   - **断言子代理**：逐条断言清单项——环境前提、可执行性、扩展性、缺口、依赖、失败模式。
   - **分析子代理**：向模糊方向延伸——检索本地技能库与接线人公开技能仓库（检索清单见 `fuzzy-dispatch.md` §4）；语义接近的候选全部纳入，逐条记来源。
3. **REWRITE（五列记账）** — 主代理改写清单，每条：谁执行了什么 / 提出了什么 / 修改了什么 / 结果 / 时间。
4. **MERGE（合并轮）** — 改写后的清单再派模糊子代理合并（同样带口径继承）。有新条目 → 回步骤 3；连续无新增 → 停，终止行进五列表。
5. **EXECUTE（销项）** — 按最终清单执行，逐条销项。

派发受阻（环境深度限制等）时换 workflow 通道或内联降级，纪律不变。

## 主代理角色

- 上下文只装：派发记录、原话表、改写清单；执行细节一律留子代理。
- 逐条可执行性结论以子代理裁定列为准；主代理做汇总、派发、销项。
- 缺细节填占位符推进。

## Rationalization Table

| 借口 | 现实 |
|---|---|
| "派子代理是烧时间" | 主代理的活是调度；上下文压子代理正是为了主代理便宜 |
| "别走流程直接写" | 清单是流程的一部分；省掉它就是替用户做决定 |
| "我自己扩一版就行" | 单轮浅扩 ≠ 轮番扩到扩不出 |
| "这轮差不多了" | 终止标准是扩不出，不是感觉够 |
| "指令看着挺全" | 完整度按可引用原文判定：三项能从用户消息逐字引出才免扩展——「内容你定」是授权信号不是参数原文 |

## Red Flags — STOP and Start Over

- 已开始读文件/写代码/搜网页，但没派过模糊子代理
- 清单里没有用户原话逐字
- 循环没走满一轮就停

以上任何一条 = 回步骤 1 重来。
